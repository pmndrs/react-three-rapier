## CSP refuses to compile WebAssembly

*(Issue #699)* With a strict `Content-Security-Policy` you get an error mentioning `unsafe-eval` or WebAssembly compilation.
You do not need `'unsafe-eval'`. WebAssembly is gated by the narrower `'wasm-unsafe-eval'` source, which does not allow
JavaScript `eval`:

```
Content-Security-Policy: script-src 'self' 'wasm-unsafe-eval'
```

It is supported by Chrome 95+, Firefox 102+ and Safari 16+. Switching to a non-compat Rapier package does not avoid this.

## Could not resolve "fs"

*(Issue #698)* This error comes from `opentype.js`, which is used by drei's `Text3D`, when your bundler targets a worker
or server runtime (for example Shopify Hydrogen). It is not caused by Rapier. Alias `fs` to `false` / mark it external for
that target, exclude `Text3D` from server bundles, or avoid `Text3D`. 3.0 removes `three-stdlib` from this library's dependencies.

## Heightfield collider errors or lets bodies fall through

*(Issues #730, #564)* A `HeightfieldCollider` with `args={[w, h, heights, scale]}` needs `heights.length === (w + 1) * (h + 1)`,
because `w` and `h` count cells and heights are per vertex. The values are column-major. Also use a positive `scale`: a negative
`scale.z` makes bodies fall through. To mirror a heightfield, rotate its body by 180 degrees around Y.

## How do I get the penetration depth of a collision?

*(Issue #768)* The `manifold` in `onCollisionEnter` is a Rapier `TempContactManifold`. Read `manifold.contactDist(i)` or
`manifold.solverContactDist(i)` for each of `manifold.numContacts()` contacts; negative values mean penetration. The manifold is
temporary, so read it inside the callback and copy values out. The depth is for the first contact, so for resting contacts use
[`onContactForce`](/advanced/contact-forces).

```tsx
<RigidBody
  onCollisionEnter={({ manifold }) => {
    for (let i = 0; i < manifold.numContacts(); i++) {
      console.log(manifold.contactDist(i), manifold.solverContactDist(i));
    }
  }}
/>
```

## How do I raycast?

*(Issue #714)* There is no `raycaster`. Use `useRapier()` and call queries on the world:

```tsx
const { world, rapier } = useRapier();
const ray = new rapier.Ray({ x: 0, y: 5, z: 0 }, { x: 0, y: -1, z: 0 });
const hit = world.castRay(ray, 10, true);
```

To know whether a body is on the floor, cast a short ray down, or use a sensor collider below it. See
[Hooks](/api/hooks#raycasting-and-queries).

## setNextKinematicTranslation does nothing

*(Issue #726)* Rapier's setters take objects, not arrays: `body.setNextKinematicTranslation({ x: 0, y: 1, z: 0 })`.
Passing `[0, 1, 0]` silently does nothing. Call it every frame (for example in `useFrame`) on a `kinematicPosition` body.

## Using drei `Html` inside a RigidBody

*(Issue #645)* `<RigidBody>` does not re-center its children. If the label looks centered, it comes from the `center` prop of `Html`, or from
centered geometry. Give the `Html` an explicit position relative to the body, or wrap it in a positioned group:

```tsx
<RigidBody>
  <mesh>...</mesh>
  <group position-y={1}>
    <Html>label</Html>
  </group>
</RigidBody>
```

## Hull or trimesh collider pivots around the wrong point

*(Issue #267)* The collider is built from the geometry as it is, in the object's local space. If the geometry is not centered on its
origin (common for models from glTF files, URDF links or hamburgers), the center of mass is off-center and the body spins around an
unexpected point or looks "heavy" on one side. Re-center the geometry (`geometry.center()`, or fix it in your modeling tool), or
wrap the mesh in a group with the opposite offset, so that the origin matches the intended pivot.

## Rotating a parent of a RigidBody after mount

*(Issue #36)* Bodies read the world transform of their parents when they are created. If you later rotate or move a physics ancestor
(for example drei `PresentationControls`, which rotates its children rather than the camera), the bodies do not follow, and the
rendered pose is computed against a stale transform. Rotate the camera instead (`OrbitControls`, `CameraControls`), or keep
physics objects outside the transformed group.

## React Native

*(Issue #383)* React Native is not supported. Rapier is WebAssembly, which the Hermes engine does not provide. Polyfills work only for
tiny scenes and are unsupported. Look at `callstack/react-native-rapier` for native bindings.

## Kinematic body passes through fixed colliders

*(Issue #694)* A kinematic body is never pushed out of other colliders by contacts. `activeCollisionTypes={ActiveCollisionTypes.ALL}` only
makes kinematic-vs-fixed pairs *report events*; it does not resolve penetration. For a player character use Rapier's kinematic
character controller (`world.createCharacterController()` with `computeColliderMovement`) or a dynamic body driven by velocity.

> [!WARNING]
> **TODO (3.0):** `useCharacterController` / `<CharacterController>` will wrap this. Not documented yet.

## Vehicle wheels react to sensors

*(Issue #693)* Rapier's raycast vehicle controller casts rays that hit sensors by default. Pass a filter flag to `updateVehicle`:

```tsx
const { rapier } = useRapier();
vehicle.updateVehicle(delta, rapier.QueryFilterFlags.EXCLUDE_SENSORS);
```

The same flag applies to `world.castRay` and the other queries.

## raweventqueue_new of undefined

Usually a duplicate or mismatched `@dimforge/rapier3d-compat` in `node_modules`, which leaves the wasm module uninitialized. Make sure
exactly one copy is installed (`npm ls @dimforge/rapier3d-compat`) and dedupe it.
